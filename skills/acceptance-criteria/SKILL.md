# Acceptance Criteria

Runtime implementation is intentionally stubbed. Generate criteria only when the parent requirement, actors, outcome, rules, and constraints are known. Include happy path, boundary, authorization, error, exception, timing, audit, and data-quality cases as relevant. Keep each criterion observable and link it to exactly identified requirements; require BA and QA review.
